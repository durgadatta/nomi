> Status: current implementation bridge; packet `designing`.

## Current Evidence

The CLI and public WASM/JS playground run calculations and a bounded report
using structural outcomes and two manual schemas. The runtime exposes execution,
inspection, sessions, capability metadata and separate target-direction records.
Research laboratories execute engine-free descriptions, exact maps, scoped pure
terms, finite premise/theory checks, typed proposals and adaptive inquiry with
independent replay. These bounded tools do not form a complete target compiler.

Shared binding/carrier/evidence responsibilities are a designing synthesis.
The data-comparison pressure program retains raw changes separately from policy
acceptance. Its tolerance predicate is deliberately non-transitive and cannot
silently define hash identity, nominal equality or a complete stream comparison.

## Open Gaps

Portable exact-Int transport, nominal construction/derived decode, real
Option/Result and exhaustive match, checked callbacks and closed local reuse
still need end-to-end target integration. Reasoning needs richer premise and
vocabulary transport, general typed/effectful source and independent numeric AD.
Resources, tasks, domain engines, distribution profiles and human/empirical
validation retain their own gates. A model result cannot mint authority or
replace domain-specific laws.

## Validation

Use the packet's commands in `config/design_passes.json` and its independent
fixtures. `python3 -m tools.design_passes check` validates routing and this record;
it does not execute the target. Browser support requires
`python3 scripts/check_web_runtime.py` and
`python3 scripts/check_web_browser.py --url https://durgadatta.github.io/nomi/web/`.
Record command outputs in ignored reports; do not accumulate dated test totals
or session narratives here. Research-model checks prove only their stated scope.
